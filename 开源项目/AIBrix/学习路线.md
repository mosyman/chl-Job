AIBrix 是基于 Kubernetes 的大模型推理平台。它不负责推理本身，推理由 vLLM 等引擎完成。它负责三件事：**请求路由到哪个 Pod、Pod 数量怎么扩缩、模型和 LoRA 怎么部署与加载**。

建议学习顺序是：先弄清整体架构，再跟着一条请求读完网关代码，然后读控制器，最后看进阶专题。

## 一、全局架构图

```
                        ┌──────────────────────────────┐
 用户请求 ────────────► │  Envoy Gateway (aibrix-eg)   │ ──────────────┐
 (OpenAI 兼容 API)      └──────────┬───────────────────┘               │ ③ 按 header
                                   │ ① ext_proc gRPC :50052             │   "target-pod"
                                   ▼                                    │   直连 Pod
                        ┌──────────────────────────────┐               ▼
                        │ gateway-plugins (cmd/plugins)│      ┌───────────────────┐
                        │ ② 解析 body → 选算法 → 选 Pod │      │ 推理 Pod (vLLM等) │
                        │    cache.Store ◄── 抓 metrics ├──────│ + aibrix runtime  │
                        └─────┬──────────────▲─────────┘      └─────────▲─────────┘
                              │ 计数/限流     │ informer                 │ 创建/扩缩/
                              ▼              │ (Pod/ModelAdapter)       │ 加载 LoRA
                        ┌──────────┐   ┌─────┴─────────────────────────┴──────┐
                        │  Redis   │   │        Kubernetes API Server          │
                        └──────────┘   └─────▲────────────────────────────────┘
                                             │ watch + Reconcile
                              ┌──────────────┴──────────────────────────────┐
                              │ controller-manager (cmd/controllers)         │
                              │ PodAutoscaler / ModelAdapter / ModelRouter   │
                              │ StormService→RoleSet→PodSet / ModelClaim ... │
                              └─────────────────────────────────────────────┘
```

**图解：**
- **数据面（上半部分）**：用户请求先到 Envoy。Envoy 通过 ext_proc 协议把请求头和请求体交给 `gateway-plugins`（①）。插件根据模型名、负载和 KV cache 情况选出一个 Pod（②），把结果写进 `target-pod` 请求头。Envoy 的 `ORIGINAL_DST` 集群读取这个头，直接连到该 Pod（③）。相关配置在 [gateway.yaml:199-202](config/gateway/gateway.yaml:199)，ext_proc 挂载配置在 [gateway-plugin.yaml:225-247](config/gateway/gateway-plugin/gateway-plugin.yaml:225)。
- **路由依据的数据**：来自插件进程内的 `cache.Store`。它通过 informer 监听 Pod 和 ModelAdapter，并定时抓取推理引擎的 metrics。跨网关副本共享的运行中请求数和限流状态存放在 Redis。
- **控制面（下半部分）**：`controller-manager` 是标准的 kubebuilder / controller-runtime 程序。它监听 AIBrix 的 CRD，执行 Reconcile，负责扩缩容、加载 LoRA，以及编排 prefill/decode 分离部署。

## 四、学习要点

1. **一个核心 label**：`model.aibrix.ai/name` 把 Deployment、Pod、HTTPRoute 和 cache 串在一起。

3. **两个插件化机制**：路由算法通过 `init()` + `Register` 注册；控制器通过 `controllerAddFuncs` 注册。
4. **遇到不懂的地方先看测试**：每个 `xxx.go` 基本都有对应的 `xxx_test.go`。测试是最准确的行为说明。

**第三步，用 PodAutoscaler 学习控制器。**

先理解它的循环：

```text
PodAutoscaler CR
       |
       v
    Reconcile
       |
       v
Validate Spec ---> Read current replicas
                           |
                           v
                    Collect metrics
                           |
                           v
                    Compute desired
                           |
                           v
                 Stabilize + apply bounds
                           |
                           v
                    Update workload
                           |
                           v
                     Update status
```

这张图描述的是自定义扩缩容路径的主要步骤：读取配置与当前副本数，收集指标，计算建议值，再经过稳定化和上下限约束，决定是否写入工作负载，并记录状态。
